## Context

`linapro-moka-report-sync` 的现有管线为：

```
GetReportData → FlattenReport → 可选 ApplyDerivedColumns → CoalesceRows
  → NormalizeColumns → preparePersonFields → Plan → BatchCreate/BatchUpdate
```

现有映射配置（`ReportMapping`）只能声明「怎么把报表列搬到 Bitable 列」，无法声明「哪些行不要」。运营的真实口径里包含时间维度过滤（例如招聘月度报表只要最近若干月份），当前只能靠 Moka 报表侧自带过滤条件满足；报表侧表达不了时无解。

约束（已与用户确认）：

- 过滤条件的时间来自**报表的日期列**（如 `申请时间`），规则里显式声明该列的解析格式。
- 阈值是**固定字面量**，不是相对当前时间的偏移量——行为可预测，改口径改配置即可。
- 比较语义是**解析成时间戳再比**，而非字符串比大小，避免两侧格式位数不一致时静默全过或全跳。
- 解析失败的行**保留**（不跳过），不做比例保护、不升级为整条映射失败。
- 转置形态（`shape: pivot`）本次不接入。

## Goals / Non-Goals

**Goals:**

- 在映射级别声明式表达「源列时间早于阈值 → 跳过该行」。
- 复用现有 `derivedColumns` 的封闭 `kind` 注册表扩展方式，新增比较方向只需加一个纯函数。
- 配置侧不出现 Go 参考时间布局（`2006-01` 之类），改用 GoFrame 的 `gtime` 方言（`"Y-m"`）。
- 未配置 `skipIf` 时行为与当前完全一致。
- 过滤逻辑为纯函数，可完整单元测试，不引入 SDK 或 I/O。

**Non-Goals:**

- 不支持相对当前时间的动态阈值（`now-3M` 之类）。
- 不支持表达式串（`"申请时间 < now"` 这种一旦开头的自由度无法收敛）。
- 不支持除 `before` 外的比较方向（`after` / `equals` / `in` 本次不做，但预留注册表扩展点）。
- 不接入 pivot 形态。
- 不改动 Moka 拉取、Lark 写入、`Plan` 及其下游。
- 不做解析失败比例保护（用户明确不需要）。

## Decisions

### 决策 1：过滤作为列派生之后的独立管线步骤

`ApplySkipRules` 插在 `ApplyDerivedColumns` 与 `CoalesceRows` 之间。

- **为何在列派生之后**：规则可以引用派生出来的列（如 `申请时间` 拆出的 `招聘月份`），配置不必重复书写解析格式；同时保留「直接对原始日期列做过滤」这一用户确认的路径，两条路都通。
- **为何在 `Coalesce` 之前**：`CoalesceRows`、`NormalizeColumns`、`preparePersonFields` 都是按行开销，被过滤掉的行没必要走完这些步骤。放在最前面能尽早丢弃死行。
- 备选：放在 `preparePersonFields` 与 `Plan` 之间（也在「Plan 之前」）。否决——死行会先跑完合并、归一化和人员解析，白做无用功；且用户反馈中「放到 plan 之前」的表述与「紧跟派生之后」在语义上并不冲突，后者更强。
- 备选：放在 `FlattenReport` 与列派生之间。否决——过滤规则无法引用派生列，配置里必须重复写解析格式。

### 决策 2：`kind` 走封闭注册表，本次只注册 `before`

与现有 `derivers`（`derive.go`）完全同构的 `skippers map[string]Skipper`，每个 `kind` 是一个纯函数：

```go
type Skipper func(row Row, rule SkipRule) (skip bool, ok bool)
```

`ok=false` 表示「无法判定」（源列为空、解析失败），调用方据此保留该行。本次只注册 `"before"`。新增比较方向（如 `after`）＝加一个纯函数 + 注册一项，管线主体不动。

- 备选：直接内联一个 `Before` 字段。否决——后续必然要加 `after`，同构注册表让扩展成本保持在「加一个函数」。
- 备选：引入通用表达式求值（CEL 之类）。否决——自由度远超当前需求，配置复杂度、依赖面和误配风险都不可控。

### 决策 3：`format` 采用 GoFrame `gtime` 方言，不暴露 Go 布局

配置写 `format: "Y-m"`，实现侧经 `gtime.StrToTimeFormat` 解析（gf 内部 `formatToStdLayout` 把 `Y`→`2006`、`m`→`01`）。

实测确认：`gtime.StrToTimeFormat("2026-01", "Y-m")` → `2026-01-01`，`("2026-09","Y-m")` → `2026-09-01`，均正确。

- **为何不用 Go 原生布局**：Go 的布局是「拿参考时刻当模板」，`"2006-01"` 里的 `2026`/`09` 是字面量而非令牌，直接拿样本值当布局会产出错位且隐蔽失败的模式（已实测 `cannot parse "-09" as "6-09"`）。配置侧不应暴露这个心智负担。
- **为何不引入 `araddon/dateparse` 之类自动猜测库**：实测 `gtime.StrToTime`（内部亦是正则+时间戳猜测）会把 `202609` 静默解析成 `1970-01-03` 而不报错。结合本插件的幂等冻结语义，一次猜错的日期会稳定写入且后续每轮被判为「无差异」不再修正。宁可解析失败留空。
- **为何仍保留 `format` 而非完全自动识别**：`format` 让「源数据的形状」成为显式契约，解析失败时有明确依据可查；完全自动识别则需要为每种可疑输入设计防护。

**时区锚定**：`gtime.StrToTimeFormat` 内部使用 `time.Local`，而现有 `ParseEpochMillisCST` 固定使用东八区（`cstZone`）。实现时 SHALL 把 gf 解析出的年月日分量重新按东八区零点锚定，保证同一份配置在不同部署时区下产生相同的时间戳，维持与既有日期链路一致的语义。

### 决策 4：两侧都解析失败时保留该行

源列值为空、或源列值与阈值任一解析失败 → `ok=false` → 该行保留，记 warn。

- 用户已明确「解析失败就留空（不跳过）」。
- 安全性论证：保留是偏向「多写」的失败方向。本插件有幂等冻结兜底（同值不重写），多同步一行的代价是有界且可观察的；反之若解析失败即丢弃，一次源数据格式变更会静默丢数据，且日志上只表现为「跳过数变多」，很难定位。
- 用户已明确不需要「解析失败比例超阈值即整条映射失败」的保护。

### 决策 5：pivot 形态忽略 `skipIf` 并记 warn

`syncMappingPivot` 已对 `derivedColumns` / `personFieldSources` 采用「忽略 + 告警」的先例，`skipIf` 沿用同一处理。pivot 的过滤语义（「早于某月的月份列不要」）需要在转置前作用于月份行，与本次的 flat 语义不同，属于独立需求，不在本次实现。

## Risks / Trade-offs

- [规则 `format` 与源列实际格式不匹配 → 全部行解析失败 → 一行都不跳，且只表现为日志 warn] → 记 warn 并在日志中带上规则标识（`kind`/`source`/`format`/`value`）与被保留的行数，使「规则未生效」可从同步结果的可观察差异中定位。用户已明确不做比例保护，此为已接受的取舍。
- [`gtime` 的 `Time.Local` 与 `cstZone` 不一致导致跨时区部署下比较结果漂移] → 决策 3 中按东八区分量重新锚定；单测固化「同一输入在不同进程时区下产出同一时间戳」。
- [配置字段名拼错（如 `formate`）导致规则静默不生效] → JSON 反序列化对未知字段无提示。单测覆盖字段反序列化；文档样例给出正确字段名。若后续需要，可考虑对未知字段做强校验，属独立改进。
- [把过滤放在派生之后，若将来某条派生规则自身依赖被过滤掉的行，语义会变得难以推理] → 当前派生规则都是逐行纯函数，不依赖行集合。若将来出现跨行派生，需重新审视本顺序。
- [用户在其它专题中已确认需要「按时间跳过」的 pivot 场景] → 本次显式排除并在文档中说明，避免被误认为已覆盖。

## Migration Plan

1. 代码合并后，未配置 `skipIf` 的映射行为不变，无需数据迁移。
2. 运营按需在 `plugin.linapro-moka-report-sync.reportMappings` 的对应映射项下追加 `skipIf` 数组；`sys_config` 改动热生效，无需重启宿主。
3. 回滚：移除 `skipIf` 配置即恢复全量同步；被跳过的历史数据从未写入 Bitable，无需清理。若需回补，在 Moka 报表侧放宽时间范围后由正常同步流程写入。

## Open Questions

- `申请时间` 的真实取值形状（`2026-01` / `2026年1月` / `2026-1` 等）尚未拿到原始 `headers`/`rows` 样本。实测 `format: "Y-m"` 只接受补零的两位数月份与 `-` 分隔符；若实际数据为其它形状，需要为 `format` 增加候选格式列表（与 `derivedColumns` 的布局数组同构）。实现时以真实样本为准，必要时在单测中固化实际形状。

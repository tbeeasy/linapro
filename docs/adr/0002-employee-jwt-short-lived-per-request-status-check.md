# 员工认证用短时 JWT + 每请求查 status，不做 refresh token

员工端签发有效期 2 小时的独立 JWT（独立签名密钥），**不设 refresh token**；`EmpAuth` 中间件在**每个请求**校验签名后再查一次员工 status，离职（status=0）即时拦截。

**为什么不做 refresh**：员工在飞书 H5 内、通过飞书免登进入。免登本身就是静默的重认证——JWT 过期时前端可无感重走免登换新 token（401→静默重登→重试）。再加一个 refresh token 是冗余。

**为什么每请求查 status（而非信任无状态 JWT 到过期）**：离职员工必须被实时禁止，不能等 token 到期。employee-core 与消费方编译进同一宿主进程，EmpAuth 是进程内中间件，每请求查 status 只是一次主键级查库（亚毫秒、可接受），换来即时离职。这也顺带取代了「token 撤销名单」——status=0 即等于即时吊销。

**后果**：token 有效期与离职生效解耦——2h 只影响被盗 token 窗口与静默重登频率，不影响离职实时性。未来若有人想「优化」掉每请求查库以追求纯无状态 JWT，会破坏实时离职，勿改。
